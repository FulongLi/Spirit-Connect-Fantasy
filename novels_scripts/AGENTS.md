# Project Instructions: 灵接科技 / 小说写作

本项目是长篇科幻小说系列《灵接科技》的创作工作区。后续涉及小说规划、章节扩写、续写、修订、审稿、人物设计、世界观整理时，默认按照项目内安装的 `novel-writing` skill 执行：

- skill path: `.codex/skills/novel-writing`
- 使用重点：章节功能、场景推进、人物出场、风格保留、现实/信息可得性约束、具体修订意见。

## 默认写作习惯

- 优先写成小说正文，不把设定说明堆成百科。
- 每个场景段落都要推动至少一件事：信息、关系、危险、决定、误解、情绪状态。
- 重要角色首次出场时，要给读者足够的锚点：身份、关系、第一印象，以及至少一个可记忆特征。
- 角色只能知道他们在当场能看见、听见、接触或合理推断出的内容。
- 修改正文时保护作者原有的梦境感、哲思感、节奏、对白和细节质地。
- 后续正文少用“不是……而是……”这类硬对照句式，尽量用动作、画面、人物反应和结构递进完成转折。

## 当前项目协作方式

- 《巨鲸陨落_V1》采用中英双版本，章节文件分别位于 `zh_md/`, `zh_html/`, `en_md/`, `en_html/`。
- 章节扩写后，同步更新 Markdown、HTML 和 README 进度。
- 用户说“继续”时，默认延续当前小说工程的下一批章节，不需要重新询问方向，除非上下文出现冲突。
- 审稿时给具体问题和修改方向，不给泛泛评价。

## 小说网页导入与整理规则

当把桌面小说工程中的 Markdown / HTML 导入网站仓库，或整理 `zh_html/`、`en_html/` 阅读页面时，统一按下面规则处理，目标是让所有小说页面结构一致、链接稳定、语言切换正常。

### 目录与文件

- 每本小说的网站目录固定为 `novels/<slug>/`，其中包含 `index.html`、`assets/reader.js`、`assets/style.css`、`zh_html/`、`en_html/`、`soundtrack/`。
- 中文章节放 `zh_html/`，英文章节放 `en_html/`。
- 中英文 HTML 文件名保持一一对应，优先使用同一个 `NN_中文标题.html` 文件名，方便阅读器在中英文之间切换。
- 文件名里的历史编号可以保留，不必为了显示编号而重命名；页面实际展示的编号以 `<title>`、`<h1>` 和目录编号为准。

### 阅读页结构

- 每个章节页保持独立 HTML，基本结构为：`<!doctype html>`、`<html lang="zh-CN/en">`、`<head>`、`<body><main>`、`<h1>`、正文段落、底部导航、`reader.js`。
- 正文使用段落 `<p>` 为主；不要把结构卡、写作说明、草稿提示、工程说明直接作为对外阅读内容。
- 章节页只保留底部一个导航，不要在标题上方再放顶部章节导航。
- 底部导航统一为上一章 / 目录 / 下一章，目录链接指向 `../index.html`。
- 导航文案必须跟随页面语言，不要中英混排：中文页只显示 `上一章` / `目录` / `下一章`；英文页只显示 `Previous` / `Index` / `Next`；禁止 `上一章 / Previous`、`目录 / Index`、`下一章 / Next` 这种混合写法。
- 章节页底部必须加载对应小说的阅读器脚本：`<script src="../assets/reader.js"></script>`。

### 版权页与前置内容

- 第一页 `00_...html` 对外固定为版权信息页。
- 英文版权页标题显示为 `Copyright`；中文版权页标题显示为 `版权信息`。
- 版权页只保留书名、作者、出版社、出版年份、版权声明、ISBN 等版权信息。
- 不要保留“书名页 / 写作说明 / 灵接科技 / 作者 著 / 献词 / 工程说明”等对外阅读无关内容。
- 作者序为全系列共用固定内容，放在版权页之后，不显示章节编号。
- 各书自己的前言可以保留，也不显示章节编号。

### 显示编号

- 版权信息页、作者序、前言等前置内容不显示数字编号。
- 正文章节从 `01` 开始连续编号。
- `<title>`、`<h1>`、首页目录中的显示编号要一致。
- 如果文件名是 `03_黑水与苏醒.html`，但它是正文第一章，页面标题应显示 `01 Black Water and Awakening` / `01 黑水与苏醒`，不要照抄文件名编号。

### 首页与双语切换

- 首页 `index.html` 负责书名、简介、封面、章节目录和 Soundtrack 入口。
- 首页所有可切换界面文案使用 `data-i18n`，翻译写在本书 `assets/reader.js` 的 `copy.zh` / `copy.en` 中。
- 章节正文不做 `data-i18n`，通过跳转到 `zh_html/` 或 `en_html/` 的同名文件完成语言切换。
- 首页描述要反映实际状态：如果英文页已经是正文阅读稿，不要再写“英文框架稿”。

### 样式与移动端

- 章节底部导航在桌面和手机端都保持一行三列：上一章/Previous 在左，目录/Index 居中，下一章/Next 在右；实际显示文案按页面语言单语输出。
- 手机端只收紧导航间距和字号，不要把三个导航按钮压成单列。
- 首页双封面使用 `cover-stack`，当前语言封面在前，另一语言封面在后。
- 手机端封面容器要用随宽度变化的高度，避免后封面溢出压住下方文字。

### Soundtrack

- 音频文件名统一使用英文 ASCII，避免中文文件名在 URL / 服务器中出问题。
- 曲目中英文显示名写在 `soundtrack/catalog.js` 的 `title.zh` / `title.en`，不要依赖文件名展示。
- 每本小说维护自己的 `soundtrack/track-name-map.md`，记录文件名、英文名、中文名、章节、时长。

### 导入后自检

导入或整理完成后，至少检查以下项目：

- 没有残留 `Draft Seed`、`structural card`、`Writing Notes`、`工程说明` 等非正文阅读内容。
- 没有残留错误目录链接，如 `index_EN.html`；章节目录链接应回到 `../index.html`。
- 每个章节页只有一个底部导航。
- 每个章节页都加载 `../assets/reader.js`。
- 版权页内容干净，作者序和前言不带显示编号。
- 正文章节显示编号从 `01` 连续递增。
- 中英同名章节文件都存在，本地相对链接能解析。
- `node --check assets/reader.js` 通过；如有条件，再打开首页测试中英切换、主题切换和章节跳转。
